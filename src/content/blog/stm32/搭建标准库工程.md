在 Keil 里新建工程，是点几下鼠标、勾几个选项；在 Linux 上，我们要自己把这些事情做一遍。这一章是整个环境篇里最"硬"的部分，但做完一次就能当模板反复用，而且你会真正弄明白一个单片机工程由哪些部分组成。

本章完成后，你会得到这样一个工程：

```text
stm32-template/
├── Start/        # 芯片相关：CMSIS 内核文件、启动文件、链接脚本
├── Library/      # ST 标准库：各个外设的驱动
├── System/       # 通用模块：延时函数等（第 4 章开始用）
├── Hardware/     # 外设模块：LED、串口等（第 6 章开始用）
├── User/         # 你的代码：main.c、中断函数、库配置
├── .clangd
└── Makefile
```

目录划分和江科大的工程一致，这样视频里的代码可以直接放进来用。

## 一、下载标准库

### 1. 从 ST 官网下载

打开 ST 官网的 [STSW-STM32054](https://www.st.com/en/embedded-software/stsw-stm32054.html) 页面（STM32F10x 标准外设库），下载 **V3.5.0** 版本。ST 官网下载需要登录账号或者填写邮箱接收下载链接。

> 江科大课程配套的资料包里也带了这个库（"固件库"文件夹），已经下载了资料包的话可以直接用里面的。

下载得到一个 zip 文件，解压：

```bash
cd ~/Downloads
unzip en.stsw-stm32054*.zip   # 文件名可能带版本号，用 Tab 补全
ls STM32F10x_StdPeriph_Lib_V3.5.0
```

### 2. 库里有什么

我们只需要其中几个目录里的文件：

```text
STM32F10x_StdPeriph_Lib_V3.5.0/
├── Libraries/
│   ├── CMSIS/CM3/
│   │   ├── CoreSupport/              # core_cm3.c/h：Cortex-M3 内核的通用定义
│   │   └── DeviceSupport/ST/STM32F10x/
│   │       ├── stm32f10x.h           # 所有寄存器的地址和位定义
│   │       ├── system_stm32f10x.c/h  # 时钟初始化（SystemInit）
│   │       └── startup/
│   │           ├── arm/              # Keil 用的启动文件 ← 不能用
│   │           └── gcc_ride7/        # GCC 用的启动文件 ← 用这个
│   └── STM32F10x_StdPeriph_Driver/
│       ├── inc/                      # 外设驱动头文件
│       └── src/                      # 外设驱动源文件
└── Project/STM32F10x_StdPeriph_Template/  # 官方模板：配置文件和中断文件
```

**最容易踩的坑**：`startup` 目录下有好几个子目录，分别对应不同编译器。Keil 用的是 `arm/`，GCC 要用 `gcc_ride7/`。两者的汇编语法不一样，用错了会报一堆汇编错误。

## 二、整理工程目录

### 1. 复制文件

先设置一个变量指向解压出来的库，后面的命令会短一些：

```bash
LIB=~/Downloads/STM32F10x_StdPeriph_Lib_V3.5.0
mkdir -p ~/stm32/stm32-template/{Start,Library,System,Hardware,User}
cd ~/stm32/stm32-template
```

复制内核和芯片相关文件到 `Start/`：

```bash
cp $LIB/Libraries/CMSIS/CM3/CoreSupport/core_cm3.{c,h} Start/
cp $LIB/Libraries/CMSIS/CM3/DeviceSupport/ST/STM32F10x/{stm32f10x.h,system_stm32f10x.c,system_stm32f10x.h} Start/
cp $LIB/Libraries/CMSIS/CM3/DeviceSupport/ST/STM32F10x/startup/gcc_ride7/startup_stm32f10x_md.s Start/
```

启动文件选 `md`（Medium Density，中容量）版本，因为 F103C8T6 的 64 KB Flash 属于中容量。

复制外设驱动到 `Library/`：

```bash
cp $LIB/Libraries/STM32F10x_StdPeriph_Driver/src/*.c Library/
cp $LIB/Libraries/STM32F10x_StdPeriph_Driver/inc/*.h Library/
```

复制配置文件和中断文件到 `User/`：

```bash
cp $LIB/Project/STM32F10x_StdPeriph_Template/{stm32f10x_conf.h,stm32f10x_it.c,stm32f10x_it.h} User/
```

ST 的文件都是 Windows 换行符，不影响编译，可以不用管。

### 2. 修一个老 bug：`core_cm3.c`

标准库自带的 `core_cm3.c` 是 2009 年的版本，里面有两个函数的内联汇编写法不严谨，用新版 GCC 编译会报错：

```text
Error: registers may not be the same -- `strexb r3,r2,[r3]'
Error: registers may not be the same -- `strexh r3,r2,[r3]'
```

原因是这两个函数的输出寄存器约束写的是 `"=r"`，编译器可能让输出和输入用同一个寄存器，而 `strexb` / `strexh` 指令不允许这样。改成 `"=&r"`（`&` 表示"这个输出寄存器不能和输入共用"）就好了。

用一条 `sed` 命令修改：

```bash
sed -i '/strex[bh]/s/"=r"/"=\&r"/' Start/core_cm3.c
grep -n 'strex[bh]' Start/core_cm3.c
```

`grep` 的输出里应该能看到两行带 `"=&r"` 的代码。也可以用 Vim 打开文件，`/strexb` 搜索后手动修改。

## 三、启动文件：上电后到 `main` 之前发生了什么

在电脑上写 C 程序时，`main` 是起点，但对芯片来说，上电后要先做很多准备工作，`main` 才能正常运行。这些工作由**启动文件** `startup_stm32f10x_md.s` 完成。它是汇编写的，不需要你修改，但值得了解它干了什么：

1. **定义中断向量表**：一张放在 Flash 最开头的表。第一项是栈顶地址，第二项是复位后要执行的函数（`Reset_Handler`），后面是各个中断的处理函数地址。芯片上电时，硬件会自动从这张表里取出栈顶地址和 `Reset_Handler` 的地址。
2. **执行 `Reset_Handler`**：
   - 把**有初始值的全局变量**（比如 `int count = 5;`）的初始值从 Flash 复制到 RAM
   - 把**没有初始值的全局变量**清零
   - 调用 `SystemInit()` 配置时钟（在 `system_stm32f10x.c` 里，默认配置成 72 MHz）
   - 调用 `main()`
3. **提供默认中断函数**：所有中断函数都有一个"弱定义"的默认版本，你在 `stm32f10x_it.c` 里写了同名函数，就会覆盖默认的。

为什么全局变量要"复制到 RAM"？因为程序烧进去以后，只有 Flash 里的内容断电不丢，变量的初始值只能存在 Flash 里；但变量运行时要被修改，Flash 不能随便写，所以要在启动时把它们搬到 RAM。

启动文件里用到了几个符号：`_sidata`、`_sdata`、`_edata`、`_sbss`、`_ebss`、`_estack`，分别表示"初始值在 Flash 里的位置""变量在 RAM 里的起止位置""栈顶在哪"。这些符号由**链接脚本**提供。

## 四、链接脚本：告诉链接器程序放在哪

### 1. 为什么要链接脚本

编译器把每个 `.c` 文件编译成一个 `.o` 文件，**链接器**再把它们合并成一个完整的程序。在电脑上，操作系统会负责把程序加载到内存，链接器用默认规则就行；在单片机上没有操作系统，必须明确告诉链接器：

- 芯片的 Flash 从哪个地址开始、有多大
- RAM 从哪个地址开始、有多大
- 代码、常量、变量分别放在哪里

Keil 根据你选的芯片型号自动生成这些信息，GCC 则需要一个**链接脚本**（`.ld` 文件）。

### 2. F103C8T6 的内存布局

查 STM32F103C8T6 的数据手册（Datasheet）的存储器映射图可以知道：

| 存储器 | 起始地址 | 大小 |
|---|---|---|
| Flash | `0x08000000` | 64 KB |
| SRAM | `0x20000000` | 20 KB |

### 3. 写链接脚本

新建 `Start/STM32F103C8Tx_FLASH.ld`：

```text
/* STM32F103C8T6 链接脚本：Flash 64K，RAM 20K */

ENTRY(Reset_Handler)

/* 栈顶放在 RAM 的最末尾，栈向低地址增长 */
_estack = ORIGIN(RAM) + LENGTH(RAM);

/* 预留给堆和栈的最小空间，链接时如果 RAM 不够会直接报错 */
_Min_Heap_Size  = 0x200;  /* 512 字节，printf 等库函数会用到 */
_Min_Stack_Size = 0x400;  /* 1 KB */

MEMORY
{
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 64K
  RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 20K
}

SECTIONS
{
  /* 中断向量表，必须在 Flash 最开头 */
  .isr_vector :
  {
    . = ALIGN(4);
    KEEP(*(.isr_vector))
    . = ALIGN(4);
  } > FLASH

  /* 程序代码 */
  .text :
  {
    . = ALIGN(4);
    *(.text)
    *(.text*)
    *(.glue_7)
    *(.glue_7t)
    *(.eh_frame)
    KEEP(*(.init))
    KEEP(*(.fini))
    . = ALIGN(4);
    _etext = .;
  } > FLASH

  /* 只读常量，比如字符串和 const 数组 */
  .rodata :
  {
    . = ALIGN(4);
    *(.rodata)
    *(.rodata*)
    . = ALIGN(4);
  } > FLASH

  .ARM.extab : { *(.ARM.extab* .gnu.linkonce.armextab.*) } > FLASH
  .ARM :
  {
    __exidx_start = .;
    *(.ARM.exidx*)
    __exidx_end = .;
  } > FLASH

  .preinit_array :
  {
    PROVIDE_HIDDEN (__preinit_array_start = .);
    KEEP (*(.preinit_array*))
    PROVIDE_HIDDEN (__preinit_array_end = .);
  } > FLASH
  .init_array :
  {
    PROVIDE_HIDDEN (__init_array_start = .);
    KEEP (*(SORT(.init_array.*)))
    KEEP (*(.init_array*))
    PROVIDE_HIDDEN (__init_array_end = .);
  } > FLASH
  .fini_array :
  {
    PROVIDE_HIDDEN (__fini_array_start = .);
    KEEP (*(SORT(.fini_array.*)))
    KEEP (*(.fini_array*))
    PROVIDE_HIDDEN (__fini_array_end = .);
  } > FLASH

  /* 有初始值的全局变量：运行时在 RAM，初始值存在 Flash，启动文件负责复制 */
  _sidata = LOADADDR(.data);
  .data :
  {
    . = ALIGN(4);
    _sdata = .;
    *(.data)
    *(.data*)
    . = ALIGN(4);
    _edata = .;
  } > RAM AT> FLASH

  /* 没有初始值的全局变量：启动文件负责清零 */
  . = ALIGN(4);
  .bss :
  {
    _sbss = .;
    __bss_start__ = _sbss;
    *(.bss)
    *(.bss*)
    *(COMMON)
    . = ALIGN(4);
    _ebss = .;
    __bss_end__ = _ebss;
  } > RAM

  /* 检查剩余的 RAM 是否够放堆和栈 */
  ._user_heap_stack :
  {
    . = ALIGN(8);
    PROVIDE ( end = . );
    PROVIDE ( _end = . );
    . = . + _Min_Heap_Size;
    . = . + _Min_Stack_Size;
    . = ALIGN(8);
  } > RAM

  .ARM.attributes 0 : { *(.ARM.attributes) }
}
```

看起来很长，但核心就三件事：

1. `MEMORY` 描述芯片有哪些存储器
2. `SECTIONS` 把代码（`.text`）、常量（`.rodata`）放进 Flash，把变量（`.data`、`.bss`）放进 RAM
3. 定义启动文件要用的 `_sidata`、`_sdata`、`_edata`、`_sbss`、`_ebss`、`_estack` 这些符号

其中 `> RAM AT> FLASH` 的意思是"运行时在 RAM，但内容存放在 Flash"，正好对应上一节说的"初始值要从 Flash 复制到 RAM"。

> 很多 F103C8T6 实际有 128 KB Flash（和 F103CB 是同一块硅片），但官方只保证 64 KB 可用。为了稳妥，这里按 64 KB 写。

## 五、写 Makefile

### 1. 完整的 Makefile

在工程根目录新建 `Makefile`：

```makefile
# ========== 工程设置 ==========
TARGET   := main
BUILD    := build
# 源文件所在目录：新建目录后加到这里即可
SRC_DIRS := Start Library System Hardware User
STARTUP  := Start/startup_stm32f10x_md.s
LDSCRIPT := Start/STM32F103C8Tx_FLASH.ld

# ========== 工具链 ==========
CC      := arm-none-eabi-gcc
OBJCOPY := arm-none-eabi-objcopy
SIZE    := arm-none-eabi-size

# ========== 编译参数 ==========
MCU  := -mcpu=cortex-m3 -mthumb
DEFS := -DSTM32F10X_MD -DUSE_STDPERIPH_DRIVER
INCS := $(addprefix -I,$(SRC_DIRS))

CFLAGS  := $(MCU) $(DEFS) $(INCS) -std=gnu11 -Wall -g3 -O0 \
           -ffunction-sections -fdata-sections -MMD -MP
LDFLAGS := $(MCU) -T $(LDSCRIPT) -Wl,--gc-sections -Wl,-Map=$(BUILD)/$(TARGET).map \
           --specs=nano.specs --specs=nosys.specs

# ========== 文件列表 ==========
SRCS := $(foreach dir,$(SRC_DIRS),$(wildcard $(dir)/*.c))
OBJS := $(addprefix $(BUILD)/,$(SRCS:.c=.o) $(STARTUP:.s=.o))

# ========== 规则 ==========
all: $(BUILD)/$(TARGET).elf $(BUILD)/$(TARGET).bin
	$(SIZE) $<

$(BUILD)/%.o: %.c
	@mkdir -p $(dir $@)
	$(CC) $(CFLAGS) -c $< -o $@

$(BUILD)/%.o: %.s
	@mkdir -p $(dir $@)
	$(CC) $(MCU) -c $< -o $@

$(BUILD)/$(TARGET).elf: $(OBJS) $(LDSCRIPT)
	$(CC) $(OBJS) $(LDFLAGS) -o $@

$(BUILD)/$(TARGET).bin: $(BUILD)/$(TARGET).elf
	$(OBJCOPY) -O binary $< $@

# 烧录：通过 ST-Link 写入芯片并复位运行
flash: $(BUILD)/$(TARGET).elf
	openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c "program $< verify reset exit"

# 启动 OpenOCD 调试服务器（第 5 章用）
debug-server:
	openocd -f interface/stlink.cfg -f target/stm32f1x.cfg

clean:
	rm -rf $(BUILD)

-include $(OBJS:.o=.d)

.PHONY: all flash debug-server clean
```

> Makefile 里规则下面的命令行**必须用 Tab 缩进**，不能用空格。从网页复制时如果变成了空格，`make` 会报 `missing separator`。在 Vim 里可以用 `:set list` 查看：Tab 显示为 `^I`。

### 2. 关键参数解释

| 参数 | 作用 |
|---|---|
| `-mcpu=cortex-m3 -mthumb` | 生成 Cortex-M3 的 Thumb 指令。**编译和链接都要加**，否则会链接到错误版本的库 |
| `-DSTM32F10X_MD` | 告诉 `stm32f10x.h` 芯片是中容量型号。Keil 工程里在"Define"一栏填的就是它 |
| `-DUSE_STDPERIPH_DRIVER` | 让 `stm32f10x.h` 包含 `stm32f10x_conf.h`，从而引入标准库的各个头文件 |
| `-g3 -O0` | 带完整调试信息（包括宏）、不优化。学习阶段调试最方便，正式项目可以改成 `-Os` 减小体积 |
| `-ffunction-sections -fdata-sections` + `-Wl,--gc-sections` | 每个函数放进单独的段，链接时删掉没用到的。标准库有很多函数用不到，这样能大幅减小程序体积 |
| `-MMD -MP` | 自动生成头文件依赖，改了 `.h` 文件后相关的 `.c` 会自动重新编译 |
| `--specs=nano.specs` | 使用精简版 C 库 newlib-nano，`printf` 等函数体积小很多 |
| `--specs=nosys.specs` | 提供空的系统调用实现，因为单片机上没有操作系统 |

`SRCS` 那一行会自动找出 `SRC_DIRS` 里所有目录下的 `.c` 文件，所以**新增源文件不用改 Makefile**，放进对应目录就行。这比 Keil 里一个个"添加文件到工程"方便。

## 六、写一个最简单的 `main.c` 测试编译

新建 `User/main.c`：

```c
#include "stm32f10x.h"

int main(void)
{
    while (1)
    {
    }
}
```

编译：

```bash
make
```

最后会看到 `arm-none-eabi-size` 打印的程序大小，类似这样：

```text
   text    data     bss     dec     hex filename
    708       8    1568    2284     8ec build/main.elf
```

| 列 | 含义 |
|---|---|
| `text` | 代码和常量，占 Flash |
| `data` | 有初始值的变量，**同时**占 Flash（存初始值）和 RAM |
| `bss` | 没有初始值的变量和预留的堆栈，占 RAM |

具体数字和编译器版本有关，能看到这个表、`build/` 目录里出现 `main.elf` 和 `main.bin`，就说明工程搭好了。

## 七、让 clangd 认识这个工程

### 1. 生成 `compile_commands.json`

```bash
make clean
bear -- make
```

`bear` 会记录 `make` 执行的每一条编译命令，在工程根目录生成 `compile_commands.json`。**以后新增了源文件或改了编译参数，重新执行一次这两条命令**。

### 2. 写 `.clangd` 配置

在工程根目录新建 `.clangd`：

```yaml
CompileFlags:
  Add: [--target=arm-none-eabi]
```

这一行告诉 clangd 按 ARM 裸机目标来分析代码。配合上一章 `.vimrc` 里的 `--query-driver` 参数，clangd 就能找到交叉编译器自带的 `stdint.h` 等头文件了。

### 3. 验证

用 Vim 打开 `User/main.c`，在第一行的 `stm32f10x.h` 上按 `gd`，应该能跳转到 `Start/stm32f10x.h`。再试着输入 `GPIO_`，会弹出标准库函数的补全列表。

## 八、用 Git 保存模板

这个工程以后每个实验都要用，建议用 Git 管理起来，并且忽略编译产物：

```bash
cd ~/stm32/stm32-template
printf 'build/\ncompile_commands.json\n.cache/\n' > .gitignore
git init
git add .
git commit -m "chore: STM32F103 标准库工程模板"
```

`.cache/` 是 clangd 生成的索引缓存。以后开始一个新实验，复制一份模板目录就行：

```bash
cp -r ~/stm32/stm32-template ~/stm32/01-led
```

## 九、可能遇到的问题

### 1. `startup_stm32f10x_md.s` 报一大堆汇编错误

多半是复制成了 Keil 的 `arm/` 目录下的启动文件，换成 `gcc_ride7/` 下的。

### 2. 链接时报 `undefined reference to '_sidata'`（或 `_estack` 等）

链接脚本里缺少这些符号的定义，或者 Makefile 里的 `LDSCRIPT` 路径写错了，检查一下文件名是否一致。

### 3. 报 `region 'RAM' overflowed`

RAM 不够用了：全局变量太大，或者堆栈预留得太多。用 `arm-none-eabi-size` 看看 `bss` 有多大，或者打开 `build/main.map` 查是哪个变量占了空间。

### 4. 链接时出现 `_close is not implemented and will always fail` 之类的警告

这是 `nosys.specs` 提供的空系统调用在提醒你：这些函数在单片机上没有实际功能。只要程序里没有用到文件操作，可以忽略。

### 5. clangd 一直报 `'stm32f10x.h' file not found`

- 确认工程根目录有 `compile_commands.json`，并且是在当前目录执行 `bear -- make` 生成的
- 确认 `.vimrc` 里 clangd 的启动命令带了 `--query-driver`
- 在 Vim 里执行 `:LspStatus` 查看 clangd 是否在运行

## 十、本章小结

- 标准库文件按 **Start / Library / User** 整理，启动文件一定要用 **`gcc_ride7`** 版本
