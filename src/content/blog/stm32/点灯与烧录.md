上一章搭好了工程，这一章让程序真正跑在芯片上：**点亮一个 LED**。这是单片机的"Hello World"，看起来简单，但它会把接线、编译、烧录整条流程走通一遍。

## 一、硬件接线

### 1. 认识最小系统板

常见的 STM32F103C8T6 最小系统板（蓝色小板）上有这些东西：

| 部件 | 说明 |
|---|---|
| 主芯片 | 中间的方形芯片，丝印是 STM32F103C8T6（或兼容芯片的型号） |
| 8 MHz 晶振 | 外部时钟源，`SystemInit` 用它倍频到 72 MHz |
| PC13 LED | 板载的用户 LED，**低电平点亮** |
| 电源 LED | 通电就亮 |
| 复位按键 | 按下芯片重新启动 |
| BOOT0 / BOOT1 跳线 | 决定从哪里启动，**两个都接 0**（从 Flash 启动） |
| 4 针 SWD 接口 | 板子一端的 4 根排针：3.3V、SWDIO（或 DIO）、SWCLK（或 CLK）、GND |

### 2. 连接 ST-Link

用 4 根母对母杜邦线，把 ST-Link 和板子的 SWD 接口**按名字一一对应**连起来：

| ST-Link 引脚 | 最小系统板引脚 |
|---|---|
| 3.3V | 3.3（或 3V3） |
| SWDIO | DIO（或 SWDIO、SWIO） |
| SWCLK | CLK（或 SWCLK） |
| GND | GND |

ST-Link 外壳侧面一般印着引脚定义，**接线前一定对照看清楚**，不同厂家的 ST-Link 排针顺序不一样。

这样接好后，ST-Link 同时给板子供电，不需要再插板子上的 USB 口。

> **不要把 ST-Link 的 5V 接到板子的 3.3V 上**，STM32 的工作电压是 3.3V。

### 3. 检查连接

插上 ST-Link，板子的电源 LED 应该亮起来。然后：

```bash
st-info --probe
```

正常的话会看到类似这样的输出：

```text
Found 1 stlink programmers
  version:    V2J37S7
  serial:     ...
  flash:      65536 (pagesize: 1024)
  sram:       20480
  chipid:     0x410
  dev-type:   STM32F1xx_MD
```

`chipid: 0x410` 表示中容量 F1 芯片，`flash: 65536` 是 64 KB。如果显示 `chipid: 0x000` 或者 `Found 0 stlink programmers`，先看本章最后的"常见问题"。

## 二、写一个延时函数

LED 闪烁需要"亮一会儿、灭一会儿"，所以先写一个延时函数。这里用 Cortex-M3 内核自带的 **SysTick 定时器**：它是一个 24 位的倒计数器，每个时钟周期减 1，减到 0 时会把一个标志位置 1。

主频是 72 MHz，就是每秒 72,000,000 个周期，所以**每微秒 72 个周期**。想延时 n 微秒，就让它从 `72 × n` 开始倒数，等它数到 0。

新建 `System/Delay.h`：

```c
#ifndef __DELAY_H
#define __DELAY_H

#include <stdint.h>

void Delay_us(uint32_t us);
void Delay_ms(uint32_t ms);
void Delay_s(uint32_t s);

#endif
```

新建 `System/Delay.c`：

```c
#include "stm32f10x.h"
#include "Delay.h"

/**
 * 微秒级延时，范围 0 ~ 233015。
 * SysTick 是 24 位计数器，最大装载值 0xFFFFFF，72MHz 下约 233 毫秒。
 */
void Delay_us(uint32_t us)
{
    SysTick->LOAD = 72 * us;   // 倒数的起始值
    SysTick->VAL = 0;          // 清空当前计数值
    // 时钟源选 HCLK（第 2 位），并启动计数（第 0 位）
    SysTick->CTRL = SysTick_CTRL_CLKSOURCE_Msk | SysTick_CTRL_ENABLE_Msk;
    // 等待计数到 0：COUNTFLAG（第 16 位）变成 1
    while (!(SysTick->CTRL & SysTick_CTRL_COUNTFLAG_Msk))
    {
    }
    SysTick->CTRL = 0;         // 关闭定时器
}

void Delay_ms(uint32_t ms)
{
    while (ms--)
    {
        Delay_us(1000);
    }
}

void Delay_s(uint32_t s)
{
    while (s--)
    {
        Delay_ms(1000);
    }
}
```

这段代码就是在练 C：`SysTick` 是一个指向结构体的指针，`SysTick->CTRL` 访问结构体里的寄存器，`&` 和 `|` 用来读写某一位。在 Vim 里把光标放到 `SysTick_CTRL_COUNTFLAG_Msk` 上按 `gd`，可以跳到 `core_cm3.h` 看到它其实就是 `(1ul << 16)`。

这个写法和江科大课程里的 `Delay.c` 效果一样，只是用宏代替了 `0x00000005`、`0x00010000` 这些数字，意思更直观。

## 三、点亮板载 LED

### 1. 标准库写法

修改 `User/main.c`：

```c
#include "stm32f10x.h"
#include "Delay.h"

int main(void)
{
    // 1. 打开 GPIOC 的时钟：STM32 的外设默认不通电，用之前必须先开时钟
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE);

    // 2. 把 PC13 配置成推挽输出
    GPIO_InitTypeDef gpio;
    gpio.GPIO_Pin = GPIO_Pin_13;
    gpio.GPIO_Mode = GPIO_Mode_Out_PP;
    gpio.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOC, &gpio);

    // 3. 循环：亮 500ms，灭 500ms
    while (1)
    {
        GPIO_ResetBits(GPIOC, GPIO_Pin_13);   // 输出低电平，LED 亮
        Delay_ms(500);
        GPIO_SetBits(GPIOC, GPIO_Pin_13);     // 输出高电平，LED 灭
        Delay_ms(500);
    }
}
```

标准库的用法几乎都是这个套路：**开时钟 → 填初始化结构体 → 调用 `XXX_Init` 传结构体指针 → 使用外设**。后面学其他外设时会反复看到。

为什么板载 LED 是低电平点亮？因为它的正极接 3.3V，负极通过电阻接 PC13。PC13 输出低电平时，LED 两端才有电压差。

### 2. 编译和烧录

```bash
make flash
```

`flash` 目标依赖 `main.elf`，所以会自动先编译，再调用 OpenOCD 烧录。在 Vim 里可以直接 `:make flash`（或者按上一章设置的 F6）。

烧录成功时，OpenOCD 的输出最后几行类似这样：

```text
** Programming Started **
** Programming Finished **
** Verify Started **
** Verified OK **
** Resetting Target **
```

看到 `Verified OK`，板子上的 PC13 LED 应该开始以每秒一次的频率闪烁了。

### 3. 这条烧录命令做了什么

```bash
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c "program build/main.elf verify reset exit"
```

| 部分 | 含义 |
|---|---|
| `-f interface/stlink.cfg` | 用 ST-Link 作为下载器 |
| `-f target/stm32f1x.cfg` | 目标芯片是 STM32F1 系列 |
| `program build/main.elf` | 把程序写进 Flash，ELF 文件里记录了写入地址 |
| `verify` | 写完读回来对比，确认没写错 |
| `reset` | 复位芯片，让新程序开始运行 |
| `exit` | 完成后退出 OpenOCD |

`interface/` 和 `target/` 这两个配置文件是 OpenOCD 自带的，在 `/usr/share/openocd/scripts/` 下。

### 4. 备用方案：st-flash

如果 OpenOCD 一时调不通，可以先用 `stlink` 包里的 `st-flash` 烧录 `.bin` 文件：

```bash
st-flash --reset write build/main.bin 0x08000000
```

`.bin` 文件里只有纯数据，没有地址信息，所以要手动指定写入地址 `0x08000000`（Flash 的起始地址）。

## 四、换一种写法：直接操作寄存器

标准库帮我们做的事情，本质上就是读写几个寄存器。为了练 C，可以试着不用库函数，直接操作寄存器实现同样的效果：

```c
#include "stm32f10x.h"
#include "Delay.h"

int main(void)
{
    // 打开 GPIOC 时钟：RCC_APB2ENR 寄存器的第 4 位
    RCC->APB2ENR |= RCC_APB2ENR_IOPCEN;

    // 配置 PC13：CRH 寄存器管 8~15 号引脚，每个引脚 4 位
    // PC13 对应第 20~23 位，写入 0b0011 表示推挽输出、50MHz
    GPIOC->CRH &= ~(0xFu << 20);   // 先清零这 4 位
    GPIOC->CRH |= (0x3u << 20);    // 再写入 0b0011

    while (1)
    {
        GPIOC->ODR ^= (1u << 13);  // 翻转 PC13 的输出电平
        Delay_ms(500);
    }
}
```

这里用到了 C 语言里几个最常用的位操作：

| 写法 | 作用 |
|---|---|
| `x \|= (1u << n)` | 把第 n 位置 1，其他位不变 |
| `x &= ~(1u << n)` | 把第 n 位清 0，其他位不变 |
| `x ^= (1u << n)` | 把第 n 位翻转 |
| `x & (1u << n)` | 读取第 n 位是 0 还是 1 |

对照《STM32F10x 参考手册》（RM0008）的 GPIO 和 RCC 章节，可以查到每个寄存器每一位的含义。在 Vim 里对 `GPIO_Init` 按 `gd` 跳进标准库源码，会发现它做的也就是这些事，只是多了很多参数检查和通用处理。

> 学习阶段建议两种写法都试一下：用标准库写项目，用寄存器写法理解原理。

## 五、外接一个 LED（对应江科大的第一个实验）

江科大的课程里，第一个实验是在 **PA0** 上接一个 LED。在面包板上这样接：

```text
PA0 ──── LED 负极（短脚）
3.3V ─── 电阻（220Ω～1kΩ）─── LED 正极（长脚）
```

然后把代码里的 `GPIOC`、`RCC_APB2Periph_GPIOC`、`GPIO_Pin_13` 分别换成 `GPIOA`、`RCC_APB2Periph_GPIOA`、`GPIO_Pin_0`，重新 `make flash` 即可。

跟着视频继续学的时候，代码可以照抄，只有两个地方和视频不一样：

1. 新建的 `.c` / `.h` 文件放进 `System/`、`Hardware/` 或 `User/` 目录，Makefile 会自动找到
2. Keil 里的"编译"和"下载"换成 `:make` 和 `:make flash`

## 六、常见问题

### 1. `Error: open failed` 或 `No ST-Link found`

OpenOCD 找不到 ST-Link：

- 用 `lsusb | grep -i st` 确认系统认出了下载器
- 有些便宜的 ST-Link 需要换个 USB 口或换根线
- 权限问题参考第 2 章的"ST-Link 和串口的权限"

### 2. `UNEXPECTED idcode` / `expected 1 of 1: 0x1ba01477`

你的芯片很可能是**国产兼容芯片**（比如 CKS32F103），它的调试接口 ID 和 ST 原厂不一样，OpenOCD 的检查不通过。让 OpenOCD 跳过这个检查：

```bash
openocd -f interface/stlink.cfg -c "set CPUTAPID 0" -f target/stm32f1x.cfg \
  -c "program build/main.elf verify reset exit"
```

注意 `-c "set CPUTAPID 0"` 必须写在 `-f target/stm32f1x.cfg` **之前**。确认可行后，把 Makefile 里 `flash` 和 `debug-server` 两个目标的命令也这样改。

### 3. `Error: init mode failed (unable to connect to the target)`

ST-Link 认出来了，但连不上芯片：

1. **检查接线**：SWDIO 和 SWCLK 是不是接反了，GND 有没有接
2. **检查 BOOT0**：跳线帽要接在 0 的位置
3. **按住复位再连接**：如果之前烧过的程序把 PA13、PA14 改成了普通 IO 口，或者进入了低功耗模式，调试接口会失效。这时按住板子上的复位键，执行烧录命令，看到 OpenOCD 开始输出后马上松开

### 4. 烧录成功了，但 LED 不闪

- 确认 LED 接的是 **PC13**。少数板子的板载 LED 接在别的引脚，看看板子背面的丝印或者商家给的原理图
- 用 `arm-none-eabi-size build/main.elf` 看看程序大小是否正常，`text` 太小说明 `main` 里的代码可能没有被编译进去
- 下一章学会用 GDB 调试后，可以单步执行看看程序卡在了哪里

### 5. 提示芯片被读保护（`Device Security Bit Set`）

一些二手板子或别人用过的板子开启了读保护。可以用 OpenOCD 解除，**解除时会擦除芯片里的全部程序**：

```bash
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
  -c "init; reset halt; stm32f1x unlock 0; reset halt; exit"
```

执行后给板子断电再上电，然后重新烧录。

## 七、本章小结

- ST-Link 和板子按 **3.3V、SWDIO、SWCLK、GND** 一一对应接线，BOOT0 接 0
- 用 **SysTick** 写延时函数，放在 `System/` 目录
- 标准库套路：**开时钟 → 填结构体 → `XXX_Init` → 使用**；也可以直接操作寄存器
- `make flash` 一条命令完成编译和烧录，看到 `Verified OK` 就成功了
- 兼容芯片报 idcode 错误时加 `-c "set CPUTAPID 0"`

下一章学习用 GDB 调试：设断点、单步执行，直接查看寄存器的值。
